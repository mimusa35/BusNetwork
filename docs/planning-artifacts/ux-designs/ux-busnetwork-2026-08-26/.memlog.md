- (decision) Visual identity follows the BRD artifact so the requirements document and the product read as one system: teal accent, Barlow Semi Condensed / Public Sans / JetBrains Mono, light and dark tokens, one status colour map. BusNetwork is a TEQ module, not a separate brand; if TEQ's design system imposes components, those win and the tokens map onto them.
- (decision) Accessibility floor WCAG 2.1 AA and layout 1280 → 768 px, taken from NFR-07 and NFR-08. Four locales per NFR-06, nb_NO default. Status is never colour alone.
- (decision) Information architecture is the BRD's six tabs in fixed order, plus shared screens S-06 trip detail, S-08 invoice, S-09 dialogs, S-10 notifications, and patterns S-11 list component, S-12 visibility rules, S-13 state catalogue.
- (decision) Vocabulary is the BRD glossary and the six status names exactly; no synonyms in the interface.
- (event) Prototype (index.html, styles.css, data.js, app-core.js, app-ui.js, app-request.js, app-invoices.js, app-main.js): all six tabs, trip detail, request wizard, invoice editor, dialogs, notifications, persona switcher, light/dark, CSV export, and a demo clock that runs the scheduler transitions. Smoke test: 722 render checks across 10 personas with no errors; pricing, first-accept-wins, the withdrawn-partner mapping, invoice totals and the Active + Closed = All reconciliation verified.
- (event) 2026-09-16 FINALIZED as v1.0 alongside BRD v1.0 and PRD v1.0.
