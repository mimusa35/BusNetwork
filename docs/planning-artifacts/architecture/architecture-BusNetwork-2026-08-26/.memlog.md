- (decision) Paradigm: a feature module inside TEQ Platform — portal UI → BusNetwork application services → Bus Network service and TEQ integrations. Dependencies point inward; adapters hold no business rules; only the lifecycle component writes a status.
- (decision) Components C-01..C-16: portal UI, list query, trip lifecycle, request and share, pricing, comments, history and audit, invoices, notifications, scheduler jobs, dashboard aggregates, export, integration adapters, consistency check, authorisation and scope, migration and analytics.
- (constraint) AR-00 platform precondition: the workspace holds no TEQ Platform source, spine or Bus Network service API, so platform-dependent items name the property required and leave the mechanism to TEQ's conventions instead of inventing it. Those items are listed under Deferred.
- (constraint) The invariants that carry the BRD's rules: AR-01 one stored status with a single writer (BR-01); AR-02 one query builder so Active + Closed = All by construction (BN-ALL-03); AR-03 atomic conditional accept (BR-03); AR-04 authorisation and department scope in the query layer (BR-09, NFR-03); AR-05 server-side field visibility by viewing company (BR-04, NFR-05); AR-06 UTC and integer minor units with one rounding function (BR-07, BR-08); AR-07 audit written in the same transaction (NFR-04); AR-08 idempotent scheduler and commands; AR-09 notifications after commit, never blocking; AR-10 invoice snapshot at decision (BN-INV-07); AR-11 coexistence without changing legacy behaviour; AR-12 consistency check flags, never overwrites.
- (event) 2026-09-16 FINALIZED as v1.0 for the R1 scope. The Deferred table is filled in when platform facts are read in, without reopening the invariants.
