- (decision) The SPEC states what engineering builds and QA verifies as capabilities, citing BRD and PRD IDs rather than re-wording requirements. Capabilities SC-01..SC-10: portal shell and navigation, one list query model, dashboard aggregates, request and share, trip lifecycle and actions, trip detail with comments and history, invoices, notifications, access and data sharing, migration and consistency.
- (decision) Constraints are the BRD's own rules — BR-01..09 and NFR-01..08 — cited by ID. Non-goals are exactly the BRD's out-of-scope list, with the destination of each item recorded in v1-boundaries.md.
- (decision) Companions: data-sharing-contract.md (TEQ trip ↔ network trip linkage and the nightly check, host/partner field visibility per BR-04, canonical status and state codes, time and money conventions, the history entry shape) and v1-boundaries.md (release slices R1/R1.1/Later, where out-of-scope work stays, which open decisions move a boundary, coexistence with the legacy screens).
- (decision) Canonical values live in one place (data-sharing-contract §3) and are imported by API, storage, analytics, exports and the prototype, so ACTIVE_SET and CLOSED_SET cannot drift.
